## Source-only work in this stack

- Quiescent-only SPSC reset on worker restart, removing stale unread
  frames and old skipped telemetry. **Precondition:** one GUI controller thread
  owns start/stop/consume; the worker is joined or not yet started.
- Per-worker `uint64_t` generation token on every published snapshot; the
  worker captures the token at thread creation rather than reading mutable
  controller state. Fail closed on generation exhaustion rather than wrap.
- Real guest lifecycle contract: 12 start/stop cycles, idempotent calls,
  pause/reset while stopped from advancing, per-body spatial invariants,
  generation fencing. It is wired only in non-queue-only builds and cannot
  pass without a genuine `.ores` native object.
- 16-lane, cache-aligned, stack/preallocated AoSoA snapshot representation.
  Pack/unpack is exactly reversible for every field including epoch/telemetry,
  but **never substitutes for the Oreslang simulation**.
- The host-only layout test checks 4096 frames and process-local C++ new/delete
  calls. It does not account for Oreslang runtime, libc, Qt or all allocator
  entrypoints.

## Native execution receipt checklist

Use the latest verified PR head, not a merge-base or other convenient SHA.
Record these independently:

1. Physics commit, Git tree SHA, clean checkout and exact source blob set.
2. Compiler source commit, Git tree SHA and `oreslang-llvmc` binary SHA-256.
3. Clang binary SHA-256, version, target triple, LLVM ABI configuration.
4. Candidate IR generated by the real compiler, IR ABI verifier outcome,
   final IR hash and object hash for *each* O0/O2 mode.
5. Native guest test output including full 1200-tick replay digest and
   lifecycle stress receipt; separate valid and negative guest fixtures.
6. Host-only layout/ring CTests, sanitizers, Qt guest/host and scheduler
   evidence as distinct groups.
7. GitHub workflow run ID, attempt, job identity, started/completed times,
   executed step names and conclusions. `steps=[]` is no execution.
8. Independent PR review and branch protection decisions, distinct from
   the technical test evidence.

## Collision milestone (future, not claimed as implemented)

- Predeclare a fixed body budget (192) and a maximum bounded candidate-contact
  capacity; insertion fails closed if exceeded. No dynamic contact queue on
  the simulation carrier.
- Deterministic broadphase: partition the fixed world into bounded cells,
  sort candidate (min-id,max-id) pairs stably, and deduplicate before a
  narrowphase pass.
- Use integer/fixed-point collision oracles with explicit product/accumulation
  bounds for squared distances and impulse denominators. Define tie rules for
  coincident centers, tangencies and corner contact ordering; avoid sqrt
  implementation drift across compiler backends.
- Validate head-on collisions, grazing/tangent pairs, coincident centers,
  wall+body same-tick impact, overload on contact capacity, sequential
  determinism and later serial/parallel equivalence.
- Keep the **actual physics dynamics in `.ores`**; the host may display,
  allocate bounded buffers and own minimal ABI primitives but must not
  silently implement the solver as a C++ replacement.
